# Streak dialog

Tapping the streak card on Home (or reaching a new streak in the dhikr counter) opens `StreakCelebrationDialog`. The entrance is staged:

1. The card fades and springs in.
2. The Rive flame pops in with squash and stretch, a glow flash and a ring of sparks, then keeps flickering with rising embers.
3. When the flame lands (~450 ms), the number rolls up from yesterday's count to today's, with a spring pop and a light haptic tick.
4. The week's days stagger in. Today's circle then fills orange and its check mark springs in.
5. The continue button fades in.

Tapping the flame replays the burst (with a haptic tick). If Android's "Remove animations" setting is on (animator duration scale 0), the number, days and button appear in their final state. The flame still flickers, because it's decorative and runs inside Rive.

## Rive flame

- Runtime: `app.rive:rive-android` 11.8.0. It's the newest release that doesn't pull in a newer Compose BOM (11.9+ requires 2025.11). It raises `lifecycle` to 2.9.4 transitively. `Rive.init` runs once, lazily, the first time the dialog opens (the library disables its startup initializer).
- Size: Rive's native library adds ~3–4 MB per ABI to an AAB download and more to a universal APK (4 ABIs).
- Fallback: if the native library or the file fails to load, `StreakFlame` shows the older Compose Canvas flame.
- Asset: `app/src/main/res/raw/streak_flame.riv` (~9 KB). It's generated by `tools/rive/streak_flame.py`, not drawn in the Rive editor, so every shape, colour and keyframe can be read and changed in code. Regenerate it with `python3 tools/rive/streak_flame.py`.

Contract (an editor-made replacement must keep it):

| Item | Name | Meaning |
|---|---|---|
| Artboard | `StreakFlame` | 300×340, flame base at bottom centre |
| State machine | `StreakFlame` | three layers: `idle` (4 s seamless flicker loop), `celebrate` (1.3 s one-shot on entry, then rests), `level` (1D blend) |
| Trigger | `celebrate` | replays the pop-in burst |
| Number | `level` | 0–3 flame size and heat. The app sets 0 for streaks under 3 days, 1 for 3–6, 2 for 7–29, 3 for 30+ |

Rive draws objects that come earlier in the file on top. The generator therefore writes particles, core, middle and outer flame, then the glow, in that order. An any-state transition can't re-enter the active state, so `celebrate` moves to an empty `rest` state when it finishes, and the trigger can fire again.

### Previewing without a device

The file was checked with Rive's web runtime (`@rive-app/canvas` 2.43.1) in headless Chromium. It loaded with the artboard, animations, state machine and both inputs; the checks captured the pop-in, squash, idle and level-3 frames; re-firing `celebrate` replayed the burst; and the render loop ran at 60 fps. To repeat: serve a page that creates `new rive.Rive({ src: 'streak_flame.riv', stateMachines: 'StreakFlame', autoplay: true, canvas })`, then screenshot it with Playwright. The file can also be dropped into the Rive editor to inspect or restyle it.

## Rive week strip

The seven-day strip is also Rive: `StreakWeekSection` (`ui/components/StreakWeekStrip.kt`) draws the circles with `app/src/main/res/raw/streak_week.riv`, generated by `python3 tools/rive/streak_week.py` (it reuses the writer in `streak_flame.py`). The day letters, the «امروز» caption and the freeze note stay Compose text, so RTL, Arabic, font scaling and TalkBack keep working; the Rive view carries a spoken summary of the week. The plain Compose strip remains as the fallback when the system's "remove animations" setting is on or Rive cannot load.

Contract (an editor-made replacement must keep it):

| Item | Name | Meaning |
|---|---|---|
| Artboard / state machine | `StreakWeek` | 336×56: seven 48 px columns, circles centred at y = 28 |
| Numbers | `day0` … `day6` | state of each day, oldest to today: 0 missed, 1 done, 2 covered by a freeze, 3 freeze pending, 4 today not yet done, 5 today done |
| Number | `rtl` | 1 mirrors the column order (today on the left) for RTL layouts; Compose passes it from `LocalLayoutDirection` |
| Trigger | `fillToday` | today's disc turns orange and the check pops in; fired once when today goes from 4 to 5 |
| Layers | `layout`, `day0`…`day6`, `enter`, `fillToday` | blend poses per day; `enter` is the staggered pop-in on load |

The day letters are aligned to the artboard's seven equal columns, so the Rive view is always drawn at the 336:56 aspect ratio across the full width of the strip.

Earlier asset verification (before the ice-badge refinement): the file was loaded with Rive's web runtime (`@rive-app/canvas` 2.43.1) in headless Chromium, which found the artboard, the nine inputs and the layers, rendered all six day states, mirrored the layout with `rtl = 1`, and played the `fillToday` fill. It was not run in the Android runtime (`rive-android` 11.8.0); check it on a device.

## Streak freeze (weekly grace day)

The streak (`StreakEngine`, shared by Home, the drawer badge and this dialog through `rememberStreakState`) forgives one missed day per week:

- A single missed day is covered when the days on **both sides** have real activity, the **three days before it** are all active (a streak must exist before it is protected), and no other day of the same week was already covered. Weeks run Saturday through Friday, like the calendar strip.
- Two missed days in a row always break the streak; freezes never chain.
- Covered days keep the chain alive but **do not add to the count**. The count is always days of real activity.
- Nothing is stored. The result depends only on which days were active, so it cannot be spent twice or drift. Achievements and the activity calendar still count real activity only, so a covered day never counts as an active day there.
- If yesterday was missed and today has no activity yet, the streak is shown as saved but pending: the strip marks yesterday with a muted ice badge without a checkmark and Home/the dialog say to practise today. If today then passes without activity, the next day the streak is 0.
- Covered days show a faceted blue ice badge in the 7-day strip (Home card and dialog), and the dialog explains it in one line. The badge has no checkmark and no inner circle, because a covered day was kept by the shield, not completed. The illustrated silhouette, bright rim and shaded facets distinguish protection from an ordinary active day. Pending protection uses a muted version of the same ice badge. `StreakFreezeBadge` draws the Compose artwork; the Rive generator uses matching geometry for the animated strip. No emoji or font glyph is used.
- `DhikrCounterScreen` and Home build the week through the same `buildWeekActivity`, so the dialog can no longer show a different streak from Home.

Tuning lives in `StreakEngine` (`MIN_ACTIVE_DAYS_BEFORE_FREEZE`, week start). `StreakEngineTest` covers the rules. Reminder schedules are unchanged.

## Sound volume

The celebration's sound effects and the checklist completion sound play on the media stream (`USAGE_GAME`). They follow the volume set with the phone's volume keys and are silent when it is at zero. They previously used the system-sounds volume, which many phones keep high and don't show on the volume keys.

The ice-badge refinement has source and asset-generation checks only; Android compilation and on-device visual verification are pending a requested build.

# Scholars and lectures («علما و مشاهیر»)

Drawer destination `scholars`. Flow: scholar list → the scholar's lectures → full-screen player.

## Data source
Managed from the admin panel and served by the backend; the app never needs a release to add a sheikh or lecture.

- `GET https://api.adhkar.ir/api/scholars` → `{ "data": [ Scholar ] }`, scholars and lectures in display order, published only.
  - Scholar: `id`, `name`, `tagline`, `bio`, `hue` (0–360, tints the generated cover art), `photoUrl` (absolute URL or null), `lectures[]`.
  - Lecture: `id`, `title`, `description`, `audioUrl` (direct https mp3/m4a, ideally range-request capable so seeking works), optional `durationSec`.
- `ScholarsRepository`: shows the last cached response (or the bundled `assets/scholars.json` on first launch/offline), refreshes silently in the background; a failed refresh keeps what is shown.
- Pull down on the scholar list to refresh from the API (Material 3 `PullToRefreshBox`, indicator just below the app bar). A failed refresh keeps the list and shows «به‌روزرسانی انجام نشد. اتصال اینترنت را بررسی کنید.».
- **Backend (nour-adhkar repo):** `scholars` and `lectures` tables serve the endpoint above; scholars and lectures are managed in the admin panel under «علما و سخنرانی‌ها» (add/edit/reorder/show-hide/delete; audio is an uploaded file up to 100 MB or an https link). Until the backend is deployed the app uses the bundled file.
- Bundled شیخ ضیایی and شیخ پردل have no lectures yet; the UI shows «به‌زودی».

## UI
- Cover: the scholar's photo (`photoUrl`, uploaded in the admin panel; loaded with Coil and cached on disk, so it shows offline after the first load). Without a photo, or while it loads, cover art is drawn in Compose (gradient tinted by `hue`, star ornament, initial). On the player the ornament rotates slowly while playing; a photo never spins.
- Player (`media/LecturePlayer.kt`, MediaPlayer with persistent local audio, one lecture at a time): play/pause, ±10 s, seek bar, speed 0.75–2×. Controls are LTR by convention. In-app playback only (no background service/notification yet).
- On first play, `LectureAudioStore` downloads the complete audio before playback, showing download progress (or an indeterminate indicator when the server omits length). It stores validated files in private `filesDir/lecture_audio`, so reopening a lecture or restarting the app reuses the saved audio without a network request. The player shows «آمادهٔ پخش آفلاین» after saving. Keys include both lecture ID and audio URL so a changed URL downloads the replacement. Downloads survive app updates; clearing app data or uninstalling removes them. These audio files are excluded from Android cloud backup and device transfer.
- Failed, interrupted, empty, truncated or undecodable downloads are never published as saved audio. Switching lectures or stopping cancels the pending request; partial files are discarded and retried on the next play. Returning to the same lecture during a download retains the existing request. Storage and network errors allow retry without silently falling back to streaming.
- The lecture player's top row includes an accessible share action. It opens Android's text share chooser with labeled title, lecturer, summary, and the existing Nour Adhkar Cafe Bazaar link. Persian/Arabic labels follow the app language; lecture content stays as supplied. The summary uses the description before the backend's «متن کامل سخنرانی» heading, stripping a leading «خلاصه» heading. Older plain descriptions are shared as supplied, limited to a 2,000-character excerpt with an ellipsis when needed. Empty summaries are explicitly marked unavailable; no summary is generated. Sharing works with cached lecture data and does not change playback or send to a recipient automatically.

## Transcripts

The description card has a copy-summary action when a supplied summary is available. It uses the same extraction as sharing, but copies the complete summary to the clipboard without truncation, title, lecturer, app link or appended transcript. Android 13+ provides clipboard confirmation; older devices show a localized toast. This action works offline from the current lecture data.

Lecture transcripts are generated by the `Lecture transcripts` GitHub workflow in the backend repository (`nour-adhkar/.github/workflows/lecture-ai.yml`, using Groq's free Whisper). An admin reviews them in the panel. Once a transcript is reviewed, `GET /api/scholars` appends it to the lecture's `description`. The app already shows that field under «درباره این سخنرانی», so older versions get the transcript too.
